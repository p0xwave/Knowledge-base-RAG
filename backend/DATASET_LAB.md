# Лаборатория датасетов и LoRA

Раздел `/lab` доступен из бокового меню после входа. Он использует
**Dataset → DatasetVersion → DatasetVersionFile** из [системы версий](DATASET_VERSIONING.md)
(PR #34). Собственной таблицы документов и второго хранилища файлов нет.
Датасеты, ранее созданные через `/api/dataset`, тоже отображаются, включая пустые.

## Пользовательский сценарий

1. Загрузите до 100 TXT/Markdown (.txt/.md) в UTF-8, суммарно до 10 МиБ.
   Оригинальные байты сохраняются в общей дедуплицированной системе. Повторная
   загрузка в тот же датасет создаёт новую полную версию, не заменяя предыдущую.
2. Выберите версию документов и модель-генератор. Новый запуск получает отдельную
   запись очереди, seed и настройки. Генератор использует существующий
   `dataset_synth.pipeline.run_synth_from_chunks`; общий Chroma не читается.
3. Успешная генерация создаёт `DatasetVersion` с `base_version_id`, файлами
   `train.jsonl`, `val.jsonl`, `prompt_contract.json`, `lab/synthesis.json` и
   дескриптором модели в `RuntimeManifest`. Документы наследуются без копирования
   blob. В интерфейсе видны связь версий, модель, параметры и метрики каждого запуска.
4. Выберите завершённый запуск синтетики и базовую модель. Создаётся **план** LoRA
   (`planned`) и дочерний снимок с `TrainingRuntime` и `lab/training.json`.
   `materialize_version(...).training_config(output_directory)` из PR #34
   восстанавливает train/validation, prompt contract и параметры. Модель не
   скачивается, GPU и суперкомпьютер не запускаются. Метрик обучения пока нет.
5. Кнопки входа/результата переходят между версиями. Имена файлов занимают не более
   двух строк; при переполнении кнопка «Все файлы» открывает полный список. Нажатие
   на имя открывает просмотр в том же окне с возвратом к списку и скачиванием.
   Текст показывается без исполнения разметки, до 128 КиБ; для остальных форматов
   доступно скачивание. Train/validation и manifest доступны и из карточки прогона.

Числа `vN` обозначают канонические версии датасета, `#N` — прогоны каждого вида
внутри датасета. Повторные генерации разными моделями и планы обучения не
перезаписывают друг друга. Проверенные результаты и ошибки сохраняются в БД.
Удаление версии через существующий API обнуляет ссылку прогона, но оставляет его
историю и исходный ID/SHA в config. Дочерние снимки сохраняют унаследованные файлы.
Удаление всего датасета удаляет его прогоны каскадно; GC остаётся общим.

## Подключение генерации

- [ ] **TODO: включить генерацию синтетики после подключения LLM.** В локальном
  окружении для ручной проверки (`.env.lab-demo`) она намеренно отключена.
  Указать `LAB_TEACHER_API_URL`, `LAB_TEACHER_MODELS` и при необходимости
  `LAB_TEACHER_API_KEY`, перезапустить backend и запустить `services.lab_worker`
  с тем же окружением. Проверить доступность генерации и worker в `/api/lab/catalog`,
  затем вручную проверить один небольшой запуск. `RAG_ENABLED` управляет RAG-чатом
  и сам по себе не включает генерацию синтетических датасетов.

Backend и отдельный worker должны использовать одну PostgreSQL и один
`DATASET_STORAGE_PATH` с правами чтения/записи. `init_db()` создаёт новые таблицы
`lab_runs`, `lab_workers` идемпотентно; пересоздавать существующие таблицы не нужно.
Устаревшая экспериментальная таблица `lab_datasets` не используется и не создаётся.

Настройки сервера (секреты только в локальном окружении; `.env` не коммитить):

- `LAB_TEACHER_API_URL`: URL доверенного OpenAI-compatible endpoint.
- `LAB_TEACHER_API_KEY`: credential endpoint, при необходимости.
- `LAB_TEACHER_MODELS`: JSON-массив разрешённых имён моделей на этом endpoint.
- `LAB_TRAINING_MODELS`: JSON-массив базовых моделей; исходный каталог содержит
  Qwen2.5-Coder-Instruct 1.5B / 3B / 7B. Это варианты плана, доступность весов
  и совместимость с будущим кластером не проверяются при сохранении.
- `LAB_CODE_REVISION`: Git SHA развернутого кода для provenance manifest.

Запуск из `backend/` в окружении приложения:

```bash
uv run --locked --package backend python -m services.lab_worker
```

Без endpoint генерация отключена; без worker новые задачи остаются в очереди и
интерфейс сообщает об этом. Worker выполняет один прогон за раз (до двух запросов
teacher внутри него); несколько workers используют PostgreSQL `SKIP LOCKED`.
Потеря heartbeat более пяти минут переводит прогон в ошибку при следующем обходе
очереди; автоматического повторения внешних запросов нет. Очередь ограничена
10 активными задачами на пользователя. Отменить можно очередь или план, не уже
выполняющуюся генерацию. Серверный лимит multipart — 11 МиБ до разбора загрузки.

## Воспроизводимость и ограничения

TXT/Markdown режутся по 3000 символов без overlap; нужны минимум два различных
фрагмента. Seed фиксирует разбиение и distractors. Exact-context holdout выполняется
до добавления отвлекающих фрагментов и отказов. Одинаковые тексты не пересекаются
между train/validation, но разные фрагменты одного документа могут попасть в обе
части. Порядок результатов teacher стабилен относительно входов; сам внешний LLM
не обязан быть детерминированным. Пустые ответы и поля неверного типа отвергаются.

Показываемые метрики синтетики — количество Q&A, train/validation, время и hashes.
Это не оценка groundedness или качества модели; отдельный judge не вызывается.
Loss и eval-метрики планов обучения пусты, без демонстрационных значений.

План сохраняет выбранные параметры, а остальные берёт из `lora_train.config`
при восстановлении. Он не является готовым заданием SLURM. Перед реальным запуском
нужно зафиксировать revision весов, полный config и окружение кластера, подключить
исполнитель и запись реальных метрик. `report_to="none"`, `trust_remote_code=False`.
Секреты endpoint не попадают в config, manifest, runtime и сообщения ошибок.

## Проверки без модели и GPU

```bash
PYTHONPATH=backend:dataset-synth:prompt-contract:lora-train \
  python -m pytest backend/tests/lab -q
```

По умолчанию тесты используют временную SQLite, пропуская проверку блокировок.
Для изолированной PostgreSQL задайте `LAB_TEST_DATABASE_URL` с БД `lab_test`:
fixture создаёт и удаляет свои таблицы, поэтому **только одноразовая тестовая БД**.
Проверки используют подставной teacher и реальные генератор, blob storage,
публикацию версий, восстановление runtime и удаление/GC. Рабочие данные, Chroma,
внешние endpoint и GPU не используются.
